Como Rodar o Qwen3.8-27B Localmente: Ollama, llama.cpp, vLLM, HuggingFace

Guia passo a passo para rodar o Qwen3.8-27B na sua máquina. Cobrimos Ollama (mais fácil), llama.cpp (mais flexível), vLLM (produção) e HuggingFace Transformers (desenvolvimento).

Pré-requisitos

Antes de começar, verifique seu hardware. O Qwen3.8-27B é um modelo denso de 27B — todos os parâmetros são carregados na memória. Consulte nosso guia de hardware para detalhes completos.

  • GPU: 16–24GB VRAM mínimo (Q4_K_M), 27–32GB para Q8/FP8, 54GB+ para BF16
  • RAM: 32GB de sistema (64GB recomendado)
  • Armazenamento: 20GB livres
  • Software: Docker (opcional), Python 3.10+ (para HF/vLLM), CUDA 12+ (para GPU NVIDIA)

Método 1: Ollama (recomendado)

Ollama é o caminho mais curto. Um comando puxa o modelo quantizado e inicia o chat.

1Instalar o Ollama

# Linux/macOS
curl -fsSL https://ollama.com/install.sh | sh

# Windows: baixar de https://ollama.com/download

2Rodar o Qwen3.8-27B

# Puxa o modelo quantizado (18GB) e inicia o chat
ollama run qwen3.8:27b

O modelo é baixado automaticamente (18GB, 256K de contexto, texto + imagem). O primeiro download leva alguns minutos.

3Versão MLX (Apple Silicon)

# Otimizada para Mac com Apple Silicon
ollama run qwen3.8:27b-mlx

4API local (servidor OpenAI-compatible)

# Ollama expõe uma API em localhost:11434
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8:27b",
    "messages": [{"role": "user", "content": "Explique atenção híbrida em 3 frases."}]
  }'
Integrações: O Qwen3.8 no Ollama já suporta Claude Code (ollama launch claude --model qwen3.8), OpenCode, Hermes Agent e OpenClaw.

Método 2: llama.cpp (GGUF)

llama.cpp oferece mais controle sobre a configuração. Ideal para ajustar contexto, quantização e offload de camadas.

1Instalar llama.cpp

# Clonar e compilar (GPU NVIDIA)
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
make GGML_CUDA=1

# Ou via Homebrew (macOS)
brew install llama.cpp

2Baixar o GGUF (Unsloth)

# Quantização Q4_K_XL da Unsloth (lançada no dia 14/ago/2026)
# Disponível em https://huggingface.co/unsloth/Qwen3.8-27B-GGUF

3Iniciar o servidor

# Caminho mais curto (puxa do HuggingFace diretamente)
llama-cli -hf unsloth/Qwen3.8-27B-GGUF:Q4_K_XL \
  --ctx-size 262144 \
  --temp 1.0 --top-p 0.95 --top-k 20

# Ou com arquivo local
llama-server -m Qwen3.8-27B-Q4_K_M.gguf \
  --ctx-size 32768 \
  --n-gpu-layers 99 \
  --port 8080

O servidor expõe uma API OpenAI-compatible em http://localhost:8080.

Parâmetros-chave: --ctx-size define o contexto máximo (comece com 32768, aumente conforme VRAM). --n-gpu-layers 99 carrega tudo na GPU; reduza se faltar VRAM.

Método 3: vLLM (servidor OpenAI)

vLLM é a melhor opção para produção: alto throughput, suporte a NVFP4 em Blackwell e API OpenAI-compatible nativa.

1Instalar vLLM (requer ≥ 0.27.1)

pip install vllm>=0.27.1

2Iniciar o servidor

# Servidor OpenAI-compatible
vllm serve Qwen/Qwen3.8-27B \
  --max-model-len 262144 \
  --reasoning-parser qwen3

3Chamar a API

curl -X POST "http://localhost:8000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3.8-27B",
    "messages": [
      {"role": "user", "content": "Escreva uma função Python de bubble sort."}
    ]
  }'
NVFP4 em Blackwell: Em GPUs Blackwell, vLLM suporta NVFP4 com 24,6 GiB e 6,6M tokens de KV — permite rodar 1M de contexto em uma única GPU. Requer vLLM 0.27.1+.

Método 4: HuggingFace Transformers

Para desenvolvimento e fine-tuning, HuggingFace Transformers oferece controle total.

1Instalar dependências

pip install transformers torch accelerate

2Carregar o modelo

from transformers import AutoProcessor, AutoModelForMultimodalLM

processor = AutoProcessor.from_pretrained("Qwen/Qwen3.8-27B")
model = AutoModelForMultimodalLM.from_pretrained(
    "Qwen/Qwen3.8-27B",
    device_map="auto",
    torch_dtype="auto"
)

3Inferência (texto + imagem)

messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": "https://example.com/image.jpg"},
            {"type": "text", "text": "Descreva esta imagem."}
        ]
    }
]

inputs = processor.apply_chat_template(
    messages, add_generation_prompt=True,
    tokenize=True, return_dict=True, return_tensors="pt"
).to(model.device)

outputs = model.generate(**inputs, max_new_tokens=512)
print(processor.decode(outputs[0][inputs["input_ids"].shape[-1]:]))
Atenção: O Qwen3.8-27B é multimodal (image-text-to-text). Use AutoModelForMultimodalLM e AutoProcessor, não AutoModelForCausalLM.

Método 5: MLX (Apple Silicon)

Para Macs com Apple Silicon, MLX é a opção mais eficiente.

# Via Ollama (recomendado)
ollama run qwen3.8:27b-mlx

# Via mlx-lm diretamente
pip install mlx-lm
mlx_lm.generate \
  --model Qwen/Qwen3.8-27B-mlx-4bit \
  --prompt "Explique atenção híbrida."

Configurações de Sampling

O Qwen3.8-27B tem dois modos com sampling otimizado:

ParâmetroThinking (padrão)Instruct
Temperature1.00.7
top_p0.950.80
top_k20—
repetition_penalty—1.5
Nunca use temperature=0 no modo thinking. O modelo entra em loop repetitivo. Sempre use temp ≥ 0.6.

reasoning_effort

Controle a profundidade do raciocínio: xhigh (máximo), medium, low. O preserve_thinking mantém o contexto de raciocínio entre mensagens — ativo por padrão.

Troubleshooting

Erro: "CUDA out of memory"

Reduza o contexto: --ctx-size 16384. Se persistir, reduza --n-gpu-layers para fazer offload parcial para CPU. Considere Q4_K_M se estiver usando Q8 ou superior.

Erro: "model not found" no Ollama

Verifique: ollama list para ver modelos instalados, ollama show qwen3.8:27b para detalhes.

Resposta repetitiva ou degradada

No modo thinking, NUNCA use greedy decoding (temperature=0). Use sempre temperature=1.0, top_p=0.95, top_k=20.

Lentidão extrema (1–5 tokens/s)

Provavelmente rodando em CPU. Verifique com nvidia-smi se a GPU está sendo usada. No llama.cpp, aumente -ngl para carregar mais camadas na GPU.

Erro: KeyError no HuggingFace

Atualize transformers: pip install --upgrade transformers. O Qwen3.8 usa arquitetura qwen3_5 — versões antigas não reconhecem.

Contexto truncado

O modelo tem 262K nativo, mas Ollama/llama.cpp podem limitar por padrão. Use --ctx-size 262144 (llama.cpp) ou OLLAMA_CONTEXT_LENGTH=262144 (Ollama).
