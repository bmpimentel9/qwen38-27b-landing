O que é o Agent Memory Leaderboard

O Agent Memory Leaderboard (AML) é um benchmark público e aberto para comparar sistemas de memória de agentes de IA — não modelos, mas a camada que grava e recupera o que o agente aprende: fatos sobre o usuário, histórico de conversas, resultados de ferramentas. Os primeiros resultados públicos saíram em 15/08, no Hacker News, e o ranking completo está no site oficial e na organização do Hugging Face.

A escala da primeira rodada: 136 times registrados e 69 frameworks completaram a avaliação inicial, segundo o anúncio oficial. Nas tabelas de Text Memory publicadas até agora estão 65 sistemas: 15 na track Commercial Products (produtos com API hospedada) e 50 na track Open-source Methods (métodos com repositório público). Uma segunda frente, Coding Agent Memory, avalia memória para tarefas de programação e recall de contexto de repositório.

O problema que o AML ataca é conhecido de quem roda agentes locais: comparar sistemas de memória era impossível porque cada um expõe uma API diferente, roda sobre um LLM diferente e se avalia com datasets diferentes. O AML padroniza as duas pontas — a interface do sistema e o protocolo de avaliação.

Como funciona: Add→Search e Answer→Eval

A metodologia desenha uma fronteira de sistema deliberadamente mínima:

  • Sistema de memória: Add → Search. O participante expõe só duas operações — Add para gravar conteúdo e Search para recuperar o que é relevante. Nada de "o sistema também responde": quem responde é o harness do benchmark, sempre o mesmo.
  • Benchmark: Answer → Eval. O harness injeta conteúdo via Add, faz perguntas que exigem o que foi gravado, gera a resposta com o fluxo controlado e avalia com um juiz padronizado (o avaliador oficial é o pipeline official-benchmark-pipelines-v3, score de 0 a 100).

Há duas rotas de participação: industry (APIs Add/Search hospedadas, com chave emitida e smoke test antes da avaliação formal) e academic (repositório GitHub público com Docker e instruções, deploy feito pelos mantenedores). A suíte pública v3 usada na avaliação referencia benchmarks conhecidos de memória conversacional — a documentação cita LongMemEval, LoCoMo, PersonaMem, BEAM e CL-Bench entre os datasets.

O detalhe mais importante para quem compara números: o score final é desdobrado em categorias por capacidade (grupos A a H no board público). É aí que aparece a variação real de cada sistema — o líder MemoraX, por exemplo, oscila de 93,5 na melhor categoria folha a 9,0 na pior.

O que os números revelam (4 leituras)

  • 1. Memória de agente está longe de resolvida. O melhor sistema do mundo, na primeira rodada padronizada, fez 58 em 100. Para calibrar: é o tipo de número que um modelo de código faz em benchmark difícil na estreia da geração. A camada de memória é o próximo gargalo dos agentes — não o modelo.
  • 2. Baselines simples continuam difíceis de bater. SQLite FTS em 22º e BM25 em 35º, ambos acima de dezenas de frameworks sofisticados. Antes de empilhar grafos de conhecimento e rerankers em cima do seu agente, meça o que uma busca textual bem afinada já entrega.
  • 3. Ninguém domina todas as capacidades. O MemoraX varia de 93,5 a 9,0 entre categorias folha (e de 89,9 a 30,0 entre os grupos principais A-H). Score agregado esconde buracos: um sistema excelente em fatos persistentes pode ser ruim em raciocínio temporal.
  • 4. O gap entre produto e método sumiu. O melhor método open-source (45,06) está colado no melhor produto comercial depois do MemoraX (45,89). Na faixa de 41-45 pontuam Cognee, Mem0, TencentDB e meia dúzia de métodos acadêmicos — a diferenciação real ainda não aconteceu.

O que muda para quem roda agente local

Para o público deste portal — agentes always-on como o Muse Glimmer 30B ou o Qwen3.8-27B servindo localmente — o AML traz três implicações práticas:

  • A fronteira Add→Search desacopla memória do modelo. Se o seu sistema de memória expõe Add e Search (via API local ou MCP), você pode trocar o modelo por baixo sem tocar na memória — e vice-versa. É a mesma separação que o stack local já usa entre servidor de inferência e aplicação.
  • Comece simples e meça. A lição do SQLite-FTS-Baseline vale dobrada localmente: um banco SQLite com FTS5 sobre bons chunks, servido ao lado do llama.cpp, é um ponto de partida honesto — e agora existem suítes públicas (LongMemEval, LoCoMo) para comparar a sua pilha com os números do leaderboard.
  • Agente 24/7 exige memória 24/7. Um modelo feito para rodar sempre só entrega valor se lembrar de ontem. O benchmark cria a linguagem comum para escolher (ou construir) essa camada — antes era marketing; agora é score.

Caveats: leia antes de citar os números

Primeira rodada, metodologia em consolidação. Estes são os resultados inaugurais do AML e o protocolo ainda está sendo documentado publicamente. Perguntas em aberto levantadas na thread do Hacker News: os scores são de execução única ou média de múltiplas execuções? Qual LLM (e qual versão) atua como juiz na etapa Eval — e o quão sensível é o ranking a essa escolha? Além disso, a track comercial avalia o produto como submetido (versão, configuração e modo de retorno variam por entrada), não o melhor esforço do fornecedor. Trate a tabela como fotografia da primeira rodada, não como veredicto final.

Perguntas frequentes

O que é memória de agente em IA?

É a camada que permite a um agente persistir e recuperar informação entre sessões e além da janela de contexto: fatos sobre o usuário, histórico de conversas, resultados de ferramentas. O modelo esquece tudo ao fechar o terminal; a memória é o que sobrevive.

Quem lidera o Agent Memory Leaderboard?

Na track Commercial Products de Text Memory: MemoraX (58,02), MemOS (45,89) e NTES-MEMORY-SMART (44,21). Na track Open-source Methods: InvMem (45,06), Refind (44,97) e ActiveMemoryIndex (44,84). Nenhum sistema passa de 60 em 100.

Como o AML avalia os sistemas?

O sistema expõe duas operações padronizadas — Add (gravar) e Search (recuperar). O benchmark injeta conteúdo, faz perguntas e avalia as respostas (Answer→Eval) com um juiz padronizado, gerando score de 0 a 100. Comerciais participam via API hospedada; open-source via repositório GitHub com Docker.

O benchmark serve para LLM local?

Serve como referência. A fronteira Add→Search desacopla memória do modelo — dá para acoplar qualquer sistema de memória ao seu modelo local. E o desempenho dos baselines mostra que uma pilha local simples (SQLite FTS ou BM25 sobre bons chunks) já é competitiva com boa parte dos frameworks.

Posso confiar no ranking já?

Com cautela. É a primeira rodada, com perguntas metodológicas em aberto (execução única vs média, qual LLM julga). Use como fotografia do estado da arte em 15/08/2026, não como compra casada.
