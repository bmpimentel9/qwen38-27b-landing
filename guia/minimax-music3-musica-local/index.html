O que é o MiniMax Music3

O MiniMax Music3 é um modelo de geração de música por texto (text-to-music) lançado pela MiniMax com pesos abertos no Hugging Face em 7 de agosto de 2026. Você entrega duas coisas — letras e uma descrição musical (caption) — e recebe uma música completa: voz cantada, arranjo, estrutura de música de verdade, em WAV estéreo.

Não é um TTS com batida. O Music3 modela música como música: seções (intro, verso, pré-refrão, refrão, ponte, instrumental, solo, final), progressão emocional, identidade vocal estável e evolução de arranjo ao longo da faixa. Saída nativa de 32 kHz estéreo (o vocoder entrega 44,1 kHz; o servidor de referência reamostra para 32 kHz).

Um detalhe que interessa ao público deste portal: o cérebro estrutural do Music3 é um LLM Qwen3 de 8B parâmetros — o Global LLM que planeja a música frame a frame foi inicializado a partir do Qwen3-8B e retreinado para tokens semânticos de música. A mesma família de modelos que analisamos aqui virou o compositor de dentro de um modelo de música local.

A arquitetura em 4 módulos (e o mito do "2,4B")

A circula por aí que o Music3 seria "um modelo de 2,4B parâmetros". Isso é meia-verdade que confunde o planejamento de hardware. Os 2,4B são só o módulo de flow matching — o que transformaria tokens em áudio. O pipeline completo soma ~11,1B:

ComponenteParâmetrosFaz o quê
Global LLM8BEstrutura musical de longo prazo. Inicializado do Qwen3-8B; prevê o primeiro codebook RVQ frame a frame (36 camadas, hidden 4096, GQA 32/8, vocab 200k).
Local LLM0,6BDetalhe acústico frame a frame: preenche os 7 codebooks residuais de cada frame via depth decoder de 4 camadas.
Flow Matching2,4BDIT (36 camadas, dim 2048) que resolve o latente do Flow-VAE por janelas de 200 frames, Euler 30 passos, CFG 1,7.
Flow-VAE Decoder123MDecodificador estilo DAC que transforma latente em forma de onda estéreo (upsampling 512x).

Por isso os requisitos de VRAM parecem estranhos à primeira vista — "2,4B que precisa de 23GB?" — e por isso o modelo baixa ~22 GB de pesos em bfloat16 (flowmatching_vae.pth 9,83 GB + qwen_7B + dav.pth 0,49 GB + módulos). Somando os módulos: 8B + 0,6B + 2,4B + 123M ≈ 11,1B. Quem planeja disco e VRAM pelo "2,4B" se dá mal.

VRAM: os três degraus (23 → 22 → 8 GB)

Os números oficiais, medidos pela Hugging Face e documentados na doc do diffusers:

ModoVRAM livreComoCusto
Full bf16~23 GBpipeline inteira na GPUmais rápido; RTX 3090/4090/5090 de 24GB
CPU offload automático~22 GBenable_auto_cpu_offloadpouca troca de peso; 22GB já não roda em 16GB
Group offloading + streaming8 GBapply_group_offloading(..., use_stream=True) no language modelmais lento; RTX 3060 Ti / 4060 / 3090 dividida
O degrau dos 8GB não é quantização — é offload. O caminho para caber em uma GPU de 8GB não é um quant menor (não há build GGUF oficial documentada para o pipeline completo), e sim group offloading em leaf_level com use_stream=True: os blocos do language model sobem para a GPU só quando executam, sob demanda, com cópias sobrepostas em CUDA streams. A doc é explícita: "additionally group-offloading the language model fits in 8 GB". É mais lento — mas é oficial, documentado e funciona.

Antes de começar: requisitos

  • GPU NVIDIA com CUDA e driver atualizado (as três rotas assumem CUDA; 8GB = RTX 3060 Ti / 4060; 24GB = RTX 3090 / 4090 / 5090).
  • ~22 GB de disco para os pesos em bfloat16 (o download via hf traz flowmatching_vae.pth de 9,83 GB + backbone Qwen3 8B + demais módulos).
  • Python 3.10+ com PyTorch CUDA (para diffusers) ou ComfyUI atualizado (interface).
  • Paciência no primeiro download — e, no modo 8GB, paciência na geração: cada música pode levar vários minutos porque o estágio autoregressivo domina o tempo.

Rota 1 — diffusers (a rota dos 8GB)

A rota recomendada para quem quer scriptar gerações e para quem tem 8GB. O suporte ao Music3 está na branch minimax-music3-integration do diffusers, como pipeline modular.

Instalação

# ambiente
python -m venv .venv && source .venv/bin/activate
pip install torch soundfile --index-url https://download.pytorch.org/whl/cu124

# diffusers com a integração Music3
pip install git+https://github.com/huggingface/diffusers@minimax-music3-integration

# pesos (opcional — o from_pretrained baixa sozinho na primeira execução)
hf download MiniMaxAI/MiniMax-Music3 --local-dir minimax_ttm

A geração mínima (~23 GB)

import soundfile as sf
import torch
from diffusers import ModularPipeline

pipe = ModularPipeline.from_pretrained("MiniMaxAI/MiniMax-Music3")
pipe.load_components(dtype=torch.bfloat16)
pipe.to("cuda")

lyrics = """[verse]
Luz da manhã atravessando o pinheiro
Cada rua quieta é nossa
[chorus]
Devagar o mundo respira
E nada mais importa agora"""

prompt = (
    "Genre: acoustic pop. BPM: 96. Key: C major. Warm and intimate, building gently into the chorus. "
    "Vocals: soft female lead, close and breathy, light stacked harmonies in the chorus. "
    "Arrangement: fingerpicked guitar and soft piano; brushed drums and upright bass enter in the chorus."
)

audio = pipe(
    prompt=prompt,
    lyrics=lyrics,
    audio_duration=60.0,
    generator=torch.Generator("cuda").manual_seed(7),
    output="audios",
)[0]

sf.write("minha_musica.wav", audio.T, pipe.sampling_rate)

A configuração de 8 GB

Dois offloads empilhados: o automático (CPU offload) para a pipeline e o group offloading streaming para o language model:

import torch
from diffusers import ComponentsManager, ModularPipeline
from diffusers.hooks.group_offloading import apply_group_offloading

manager = ComponentsManager()
manager.enable_auto_cpu_offload(device="cuda")
pipe = ModularPipeline.from_pretrained(
    "MiniMaxAI/MiniMax-Music3", components_manager=manager
)
pipe.load_components(dtype=torch.bfloat16)

# Só é preciso abaixo de ~22 GB livres — mais lento, mas cabe em 8 GB
apply_group_offloading(
    pipe.language_model,
    onload_device=torch.device("cuda"),
    offload_type="leaf_level",
    use_stream=True,
)

Com isso, a mesma pipe(...) do exemplo anterior roda em uma RTX 4060 de 8GB. O estágio autoregressivo (25 frames por segundo de áudio) domina o tempo de geração — espere alguns minutos por minuto de música, não segundos.

Rota 2 — SGLang-Omni (servidor oficial)

Se a intenção é servir o Music3 — um serviço local que responde em API — a rota oficial é o SGLang-Omni, o mesmo runtime que o model card recomenda. Ele expõe a API /v1/audio/speech compatível com o cliente OpenAI:

# instalar conforme o guia oficial de instalação do sglang-omni
CUDA_VISIBLE_DEVICES=0 sgl-omni serve --model-path MiniMaxAI/MiniMax-Music3 --port 8000

# gerar (letra em input, descrição em instructions)
curl http://127.0.0.1:8000/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMaxAI/MiniMax-Music3",
    "input": "[Verse]\nSunday morning, quiet and slow\n[Chorus]\nTake it easy, take it slow",
    "instructions": "A melancholic lo-fi hip-hop track with a mellow piano riff, soft vinyl crackle, and a slow steady drum beat at 85 BPM",
    "response_format": "wav",
    "seed": 42,
    "max_new_tokens": 750
  }' \
  --output song_1.wav

Detalhes que valem ouro e estão no cookbook oficial:

  • max_new_tokens conta frames a 25 fps — 750 frames ≈ 30 segundos. É teto, não meta: o modelo encerra sozinho com o token de fim de áudio.
  • Tags de seção em linha própria — a normalização descarta texto na mesma linha da tag: [Verse]\nLetra funciona; [Verse] Letra canta sem essa linha, sem aviso.
  • Configuração de 2 GPUs: CUDA_VISIBLE_DEVICES=0,1 coloca o estágio AR na primeira e o DIT/DAV na segunda — útil para 2×8GB.

Rota 3 — ComfyUI (a mais fácil)

Para quem já usa ComfyUI, o suporte é nativo e oficial: atualize o ComfyUI, abra Template Library → Audio → MiniMax Music 3 Text to Music e siga o popup que baixa os modelos. A documentação oficial da Comfy mantém o tutorial completo, e os pesos reempacotados (diffusion model, text encoder e VAE prontos para os nodes) estão no Comfy-Org/MiniMax-Music-3 — o espelho mais baixado do modelo (285 mil downloads contra 11,7 mil do repo original na data desta publicação).

É a rota com menor fricção para experimentar prompts — sem Python, com workflow visual editável — mas é também a rota em que você tem menos controle sobre offloads finos, então trate-a como laboratório de prompts, não como o caminho dos 8GB.

O que roda no hardware brasileiro típico

Cruzando os três degraus de VRAM com as placas mais comuns no mercado brasileiro de reposição:

GPUVRAMVeredito Music3
RTX 3060 Ti / 40608 GBRoda no modo streaming — group offloading leaf_level, mais lento. O candidato real do "8GB de VRAM" do título.
RTX 4060 Ti 16GB / 5060 Ti 16GB16 GBGap desconfortável: os ~22GB do offload automático não cabem. Recorra ao group offloading (cabe folgado) ou aguarde quantizações comunitárias maduras.
2× RTX 3060 Ti ou 2× 40608+8 GBRota SGLang-Omni com estágios divididos por GPU (AR na primeira, DIT/DAV na segunda).
RTX 3090 (usada, mercado BR forte) / 4090 / 509024 GBFull bf16 (~23 GB) — a experiência completa, sem offload.

Como referência da casa: explicamos aqui o esforço de encaixar um LLM de 27B em 16GB via quantização GGUF — lá o caminho é quant menor; aqui, em 2026, o caminho dos 8GB é offload estruturado. Ferramenta diferente, mesma lição: quanto de VRAM você tem importa mais do que quantos parâmetros o modelo tem. Para o panorama geral de placas por caso de uso, veja o guia de hardware local.

Prompts em português: letra + caption

O controle do Music3 vem de duas entradas complementares — e a doc é explícita de que a caption é o controle mais forte que você tem: captions vagas dão arranjos genéricos; nomear instrumentos, andamento e caráter de produção dá a música que você pediu.

  • Letra (input): as palavras cantadas, com tags de seção cada uma em linha própria — [Intro], [Verse], [Pre-Chorus], [Chorus], [Post-Chorus], [Bridge], [Instrumental], [Solo], [Outro].
  • Caption/descrição (instructions): estilo, emoção, voz, instrumentação, produção. Para máximo controle, a MiniMax recomenda a estrutura em três blocos: metadados globais (gênero, BPM, tom, escala, progressão emocional), detalhes vocais (gênero vocal, timbre, performance, harmonias) e arranjo (instrumentos primário/secundários, groove, texturas).

Exemplo 1 — MPB acústica intimista (60s)

lyrics = """[verse]
Manhã de domingo devagar
Sol passando pela janela do bar
[chorus]
Deixa o tempo passar
A gente não tem hora pra voltar"""

prompt = (
    "Genre: Brazilian MPB, acoustic. BPM: 82. Key: G major. Intimate and warm, "
    "gentle emotional build into the chorus. "
    "Vocals: soft female lead in Brazilian Portuguese, close and breathy, "
    "light stacked harmonies in the chorus. "
    "Arrangement: nylon-string fingerpicked guitar and soft piano; brushed drums "
    "and upright bass enter in the chorus; warm, natural production."
)

Exemplo 2 — lo-fi hip-hop instrumental

lyrics = "[Intro]\n(instrumental)"

prompt = (
    "Genre: lo-fi hip-hop, instrumental only. BPM: 78. "
    "Mellow piano riff, soft vinyl crackle, slow steady drum beat, "
    "warm sub bass, jazzy chords, late-night study atmosphere."
)

Letras são obrigatórias e não podem ser vazias — para instrumentais, o cookbook oficial recomenda pedir "instrumental" na caption e manter a letra mínima, como acima.

Exemplo 3 — arena rock com verso em português

lyrics = """[verse]
Crescemos ouvindo estádio cheio
Rádio pirata no fim do mundo
[chorus]
A gente é o fogo que não apaga
Queimando contra o céu"""

prompt = (
    "Genre: arena rock anthem. BPM: 130. Key: E minor. "
    "Confident and gritty, building tension through verses before a wide, soaring chorus. "
    "Vocals: powerful male lead in Brazilian Portuguese, gravelly texture, melodic in the refrain. "
    "Arrangement: distorted electric guitars, punchy live drums, wide stereo image, "
    "lightly compressed; extended guitar solo after the second chorus."
)

Licença: posso usar comercialmente?

Sim, na maioria dos casos — com regras. A MiniMax-Music3 Community License permite uso comercial dos pesos e das músicas geradas sob três condições:

  • Atribuição na interface: produtos ou serviços comerciais que usam o modelo devem exibir "MiniMax-Music3" prominentemente na UI.
  • Limite de receita: se o seu grupo fatura mais de US$ 20 milhões/ano com produtos que usam o modelo, é preciso autorização prévia por escrito (api@minimax.io).
  • Serviços de geração: se você hospeda um serviço que gera músicas para terceiros, deve implementar e manter salvaguardas técnicas contra usos que violem a licença (incluindo violação de direitos de terceiros).

Não é Apache 2.0 como o Qwen3.8-27B — é uma community license no estilo Llama: aberta para quase todos, com cláusulas para quem escala. Para projeto indie, agência ou conteúdo monetizado, o caminho está aberto; leia o texto integral no LICENSE do repo.

Limitações: o que esperar (e o que não)

Português cantado: funciona, com ressalvas. O model card demonstra geração em múltiplos idiomas e a comunidade reporta letras em pt-BR sendo cantadas corretamente. As ressalvas práticas: (1) pronúncia de algumas palavras pode exigir ajuste — o truque da comunidade é escrever a letra como soa (abafo fonético) quando uma sílaba sai errada; (2) a caption/descrição funciona melhor em inglês, onde o modelo foi treinado nas descrições estruturadas; (3) não há como fixar uma voz de referência como em TTS — o que controla a voz é a descrição textual dela.
  • Tempo de geração: em 8GB, espere minutos por minuto de áudio. O estágio autoregressivo a 25 fps domina; não é realtime.
  • Não existe "voz própria": não há reference speaker, voice ou temperature ajustáveis na API SGLang — o que você controla é letra, caption, seed e duração.
  • Duração é teto: audio_duration/max_new_tokens limitam o máximo; o modelo decide quando terminar. Música de 5 minutos completos pode exigir cap alto e sorte com a seed.
  • Offline de verdade: por outro lado — sem API key, sem telemetria, sem custo por geração. Depois dos ~22GB baixados, a música é sua e do seu disco.

Perguntas frequentes

Quanto de VRAM o MiniMax Music3 precisa?

~23 GB em bfloat16 completo; ~22 GB livres com CPU offload automático; 8 GB com group offloading leaf_level em modo streaming sobre o language model. O último é mais lento, mas é a rota oficial documentada pela Hugging Face para GPUs de entrada.

Quais os parâmetros do MiniMax Music3?

~11,1B somados: Global LLM de 8B (inicializado do Qwen3-8B), Local LLM de 0,6B, Flow Matching de 2,4B e Flow-VAE de 123M. O "2,4B" que circula é só o módulo de flow matching.

O MiniMax Music3 funciona em português?

Sim — letras em português são cantadas (model card demonstra multi-idioma; comunidade reporta pt-BR funcionando). Pronúncia pontual pode exigir abafo fonético na letra, e a caption funciona melhor em inglês. Não dá para fixar voz de referência.

Posso usar as músicas comercialmente?

Sim, sob a MiniMax-Music3 Community License: exiba "MiniMax-Music3" na UI do produto comercial; acima de US$ 20 milhões/ano de receita do grupo, exige autorização prévia por escrito; serviços hospedados de geração precisam manter salvaguardas anti-abuso.

diffusers, SGLang-Omni ou ComfyUI — qual escolher?

diffusers para script e para os 8GB (única rota com group offloading documentado); SGLang-Omni para servir com API compatível OpenAI e dividir estágios em 2 GPUs; ComfyUI para experimentar prompts com workflow visual oficial e pesos reempacotados.

Quanto tempo de música o Music3 gera?

Músicas completas de até 5 minutos com estrutura real. Em SGLang, max_new_tokens conta frames a 25 fps (750 ≈ 30s); o modelo encerra sozinho com token de fim de áudio — o parâmetro é teto, não meta.
