The quick answer

The fastest path is a single command: ollama run qwen3.8:27b — an 18 GB download that brings 256K of native context and native vision. You need at least 16–24 GB of free VRAM for the 4-bit model: 16 GB works with IQ4_XS (15.71 GB measured) plus quantized KV cache (~20 t/s on an RTX 4070 Ti Super); 24 GB runs Q4_K_M (17.11 GB) with headroom. For production serving with an OpenAI-compatible API, use vLLM or SGLang — both below with copy-paste commands.

Three commands to start: 
# 1. Ollama — easiest, 18 GB, text + image
ollama run qwen3.8:27b

# 2. llama.cpp — GGUF, more control (pulls from Hugging Face)
llama-server -hf unsloth/Qwen3.8-27B-GGUF:Q4_K_XL --ctx-size 32768 --n-gpu-layers 99

# 3. vLLM — production, OpenAI-compatible API on :8000
vllm serve Qwen/Qwen3.8-27B --max-model-len 262144 --reasoning-parser qwen3

Below: measured VRAM per quantization, the four methods step by step, the sampling settings Qwen recommends (never temperature=0 in thinking mode) and the troubleshooting that covers the real failure modes. Full measured numbers: why it is slow and how to fix it.

What you need: hardware and VRAM

Qwen3.8-27B is a dense 27B model — every parameter is loaded into memory. Check your hardware before starting.

  • GPU: 16–24 GB VRAM minimum (Q4_K_M), 27–32 GB for Q8/FP8, 54 GB+ for BF16
  • RAM: 32 GB system (64 GB recommended)
  • Storage: 20 GB free
  • Software: Docker (optional), Python 3.10+ (for HF/vLLM), CUDA 12+ (NVIDIA GPUs)

Method 1: Ollama (recommended)

Ollama is the shortest path. A single command pulls the quantized model and starts the chat.

1Install Ollama

# Linux/macOS
curl -fsSL https://ollama.com/install.sh | sh

# Windows: download from https://ollama.com/download

2Run Qwen3.8-27B

# Pulls the quantized model (18 GB) and starts the chat
ollama run qwen3.8:27b

The model downloads automatically (18 GB, 256K context, text + image). The first download takes a few minutes.

3MLX version (Apple Silicon)

# Optimized for Apple Silicon Macs
ollama run qwen3.8:27b-mlx

4Local API (OpenAI-compatible server)

# Ollama exposes an API on localhost:11434
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8:27b",
    "messages": [{"role": "user", "content": "Explain hybrid attention in 3 sentences."}]
  }'
Integrations: Qwen3.8 in Ollama already works with Claude Code (ollama launch claude --model qwen3.8), OpenCode, Hermes Agent and OpenClaw.
Deep dive: the full Ollama guide (PT-BR) — all tags (18–56 GB), custom Modelfile, MTP tag qwen3.8:27b-mtp-q4_K_M.

Method 2: llama.cpp (GGUF)

llama.cpp gives you full control over the configuration — ideal for tuning context, quantization and layer offload.

1Install llama.cpp

# Clone and build (NVIDIA GPU)
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
make GGML_CUDA=1

# Or via Homebrew (macOS)
brew install llama.cpp

2Download the GGUF (Unsloth)

# Unsloth Q4_K_XL quantization (released on August 14, 2026)
# Available at https://huggingface.co/unsloth/Qwen3.8-27B-GGUF

3Start the server

# Shortest path (pulls from Hugging Face directly)
llama-cli -hf unsloth/Qwen3.8-27B-GGUF:Q4_K_XL \
  --ctx-size 262144 \
  --temp 1.0 --top-p 0.95 --top-k 20

# Or with a local file
llama-server -m Qwen3.8-27B-Q4_K_M.gguf \
  --ctx-size 32768 \
  --n-gpu-layers 99 \
  --port 8080

The server exposes an OpenAI-compatible API at http://localhost:8080.

Key parameters: --ctx-size sets the maximum context (start with 32768, raise it as VRAM allows). --n-gpu-layers 99 loads everything on the GPU; reduce it if you run out of VRAM.
MTP speculative decoding is off by default — add --spec-type draft-mtp to enable it. A documented RTX 3090 goes from ~31.6 to 74 t/s (+134.5%).
Deep dives: the IQ4_XS recipe for 16 GB (PT-BR) (~20 t/s on the RTX 4070 Ti Super) and 256K context on 24 GB (PT-BR) (50.44 tok/s measured).

Method 3: vLLM (OpenAI-compatible server)

vLLM is the best option for production: high throughput, NVFP4 support on Blackwell and a native OpenAI-compatible API.

1Install vLLM (requires ≥ 0.27.1)

pip install vllm>=0.27.1

2Start the server

# OpenAI-compatible server
vllm serve Qwen/Qwen3.8-27B \
  --max-model-len 262144 \
  --reasoning-parser qwen3

3Call the API

curl -X POST "http://localhost:8000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3.8-27B",
    "messages": [
      {"role": "user", "content": "Write a Python bubble sort function."}
    ]
  }'
NVFP4 on Blackwell: on Blackwell GPUs vLLM supports NVFP4 with 24.6 GiB and 6.6M KV tokens — enough to run 1M of context on a single GPU. Requires vLLM 0.27.1+.
Deep dive: the full vLLM guide (PT-BR) — production flags, prefix caching, MTP acceptance 0.77–0.90 and 6 real open bugs with workarounds.

Method 4: SGLang (FP8, max throughput)

SGLang is the top-throughput path on a single GPU: it serves the official FP8 checkpoint (30.89 GB) with an OpenAI-compatible API on port 30000. The SGLang team measures 206.1 tok/s on a single RTX 5090 with NVFP4 + DSpark speculative decoding. Installation follows the official SGLang cookbook.

1Install SGLang (uv)

pip install --upgrade pip
pip install uv
uv pip install sglang

2Serve the official FP8 checkpoint

python -m sglang.launch_server \
  --model-path Qwen/Qwen3.8-27B-FP8 \
  --reasoning-parser qwen3 \
  --tool-call-parser qwen3_coder \
  --context-length 131072

On unified memory (Mac, Strix Halo) keep --mem-fraction-static 0.50 — 0.95 silently skips CUDA graph capture and falls back to eager mode.

Deep dive: the full SGLang + FP8 guide (PT-BR) — install via uv or Docker, MTP/EAGLE in the checkpoint, bench_serving validation and SGLang × llama.cpp/Ollama comparison. Reference: official SGLang cookbook.

Method 5: HuggingFace Transformers + MLX (development / Apple Silicon)

For development and fine-tuning, HuggingFace Transformers gives you full control. For Apple Silicon, MLX is the most efficient path.

1Install dependencies

pip install transformers torch accelerate

2Load the model

from transformers import AutoProcessor, AutoModelForMultimodalLM

processor = AutoProcessor.from_pretrained("Qwen/Qwen3.8-27B")
model = AutoModelForMultimodalLM.from_pretrained(
    "Qwen/Qwen3.8-27B",
    device_map="auto",
    torch_dtype="auto"
)

3Inference (text + image)

messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": "https://example.com/image.jpg"},
            {"type": "text", "text": "Describe this image."}
        ]
    }
]

inputs = processor.apply_chat_template(
    messages, add_generation_prompt=True,
    tokenize=True, return_dict=True, return_tensors="pt"
).to(model.device)

outputs = model.generate(**inputs, max_new_tokens=512)
print(processor.decode(outputs[0][inputs["input_ids"].shape[-1]:]))
Important: Qwen3.8-27B is multimodal (image-text-to-text). Use AutoModelForMultimodalLM and AutoProcessor, not AutoModelForCausalLM.

4MLX (Apple Silicon)

# Via Ollama (recommended)
ollama run qwen3.8:27b-mlx

# Or via mlx-lm directly
pip install mlx-lm
mlx_lm.generate \
  --model Qwen/Qwen3.8-27B-mlx-4bit \
  --prompt "Explain hybrid attention."

Sampling configuration: thinking vs instruct

Qwen3.8-27B has two modes with optimized sampling:

Parameter Thinking (default) Instruct
Temperature1.00.7
top_p0.950.80
top_k20—
repetition_penalty—1.5
Never use temperature=0 in thinking mode — the model loops. Always use temp ≥ 0.6.

reasoning_effort

Control reasoning depth: xhigh (maximum), high, medium, low. preserve_thinking keeps the reasoning context between messages — on by default. For the full recipe, see the reasoning configuration guide (PT-BR).

Frequently asked questions

How much VRAM do I need to run Qwen3.8-27B?

16–24 GB for the 4-bit model: IQ4_XS (15.71 GB) fits 16 GB with quantized KV cache and short context; Q4_K_M (17.11 GB) needs 24 GB with headroom; Q8_0 (29.05 GB) and FP8 (30.89 GB) ask for 32 GB+; add 2–6 GB of context/KV cache overhead.

Can Qwen3.8-27B run on 16 GB?

Yes — IQ4_XS (15.71 GB measured on Hugging Face) plus quantized KV cache (q8_0) and n-gram speculative decoding: ~20 t/s on an RTX 4070 Ti Super; UD-Q3_K_XL (13.44 GB) if you need 64K+ context.

Which quantization should I choose?

Sweet spot: Q4_K_XL/Q4_K_M (~16–18 GB) on 24 GB; IQ4_XS (15.71 GB) for 16 GB; Q5_K_M (19.83 GB) with 27 GB+; Q6/Q8 (23–30 GB) with 40 GB+; official FP8 (30.89 GB) for SGLang/vLLM.

How do I make Qwen3.8-27B faster?

Order of payoff: thinking off or medium (2.06×), MTP on (--spec-type draft-mtp, off by default), KV cache q8_0, RDNA4 Q4/Q8 only, Vulkan shader rebuild, --mem-fraction-static 0.50 on SGLang with unified memory.

Does MTP speculative decoding work in Ollama?

There is no flag: MTP ships as separate Ollama tags (qwen3.8:27b-mtp-q4_K_M); Ollama swaps the chat template (reasoning_effort cannot be lowered via Ollama; use llama-server --jinja); in llama.cpp the drafter is a separate GGUF ("model has unused tensor blk.64.nextn" = off).

How many tokens per second does Qwen3.8-27B run at?

206.1 tok/s on an RTX 5090 (SGLang, NVFP4 + DSpark); 59.2 tok/s on a Radeon AI PRO R9700 (Vulkan Q8_0 + MTP, 64K context); 50.44 tok/s at 262,144 context on 24 GB; 41.5 tok/s on an RTX 3090 (UD-Q4_K_XL); 17.3 tok/s on Strix Halo (Ollama/Vulkan Q4_K_M); ~9.7 tok/s on an RTX 3060 12 GB.

Is Qwen3.8-27B slower than Qwen3.6-27B?

No — raw decode is faster: 17.3 vs 12.4 tok/s on the same machine and quant (a gap attributed to Unsloth's GGUF compilation). What feels slow is behavior: thinking defaults to xhigh and generates thousands of reasoning tokens before the answer.

Can it run 256K context on a 24 GB GPU?

Yes — the Q4 KV cache (48+16 hybrid layers) is ≈ 4.25 GiB: a third-party measurement (RTX PRO 4000 Blackwell, piszczek.pl) sustains 50.44 tok/s average with all 262,144 tokens; 12.61 tok/s with the cache full (261.5K).

Why is it slower than a 35B MoE model?

A dense model activates all 27B parameters per token; a MoE activates ~3B. On the same Strix Halo: 27B dense at 10.6 tok/s (Q5_K_M) vs 35B MoE at 56.6 tok/s — 5.3×. The dense trades throughput for quality-per-parameter and agentic strength.

What is a good tok/s for a local LLM?

Human reading speed is ~5–7 tok/s, so 10 tok/s already feels like reading pace and 100+ moves the bottleneck to tool calls. At 10 tok/s, a 20K-token thinking pass becomes half an hour — the reasoning_effort dial matters more than raw tok/s.
