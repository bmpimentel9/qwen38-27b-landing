Lemonade v11.6: serving de LLM local com GPU e NPU — a alternativa AMD ao Ollama

Enquanto o Ollama domina a conversa sobre LLM local, o Lemonade SDK segue um caminho próprio: um servidor local que orquestra GPU e NPU, com foco explícito em hardware AMD. A release v11.6.0 saiu em 14/08 — e traz o Muse Glimmer 30B direto no catálogo.

O que é o Lemonade

O Lemonade SDK é um projeto open-source (C++/Python) que serve modelos de linguagem localmente com API compatível com OpenAI, orquestrando diferentes runtimes de inferência — ONNX Runtime e llama.cpp — sobre GPU e NPU. Os tópicos do repositório contam a história por si: amd, rocm, radeon, ryzen, npu, llm-inference, mcp-server, openai-api.

A premissa é diferente do Ollama: em vez de ser "o Docker dos LLMs locais" com um runtime único, o Lemonade atua como camada de serving e roteamento — escolhe o backend certo (ONNX Runtime DirectML/Vulkan/ROCm, llama.cpp, NPU) conforme o modelo e o hardware, expõe endpoint OpenAI padronizado e ainda inclui um MCP server embutido para plugar o servidor diretamente em clientes e agentes que falam Model Context Protocol. O projeto tem 5.374 stars, commits no dia 16/08 e binários oficiais para Windows, Ubuntu, Debian, Fedora e macOS.

O que chegou na v11.6

A release v11.6.0, publicada em 14/08/2026, traz como destaques do changelog oficial:

  • Muse Glimmer 30B GGUF no catálogo embutido do llama.cpp, com draft decoding (speculative decoding via drafter), visão e tool-calling — o modelo de agentes always-on da Meta que analisamos ontem, agora a um comando de distância no Lemonade.
  • Backend ROCm do llama.cpp para GPUs AMD Instinct MI100, MI200, MI210 e MI250 no Linux — a lista de data centers da AMD ganhando caminho oficial de inferência local via llama.cpp.
  • Backend experimental TheNoise (ROCm) de geração de imagem, levando os modelos Anima e Krea-2 para as iGPUs Strix Halo e Strix Point — o mesmo segmento de hardware da máquina de referência deste portal.
  • lemonade alias: apelidos próprios para modelos, com listagem em /v1/models ciente de alias e endpoints de administração.
  • lemonade bench com cenários de visão opt-in para modelos multimodais.

Há também breaking changes relevantes para quem já rodava versões anteriores: /v1/audio/speech com formato não-PCM (ex.: mp3) no Kokoro agora retorna HTTP 400 em vez de devolver PCM silenciosamente; quants GGUF em subpastas de extra_models_dir passam a aparecer como entradas individuais em /v1/models; e o layout dos MSI do Windows mudou (automação que lia lemonade.msi do artifact antigo precisa ser repontada).

O caso AMD: por que isso importa

Quem roda LLM local em GPU AMD conhece o terreno: CUDA é cidadã de primeira classe em quase todo stack; ROCm historicamente exige paciência; e a rota pragmática costuma ser Vulkan via llama.cpp. O Lemonade nasceu do lado AMD da força — a origem do projeto está ligada ao ecossistema Ryzen AI/Radeon — e a v11.6 empurra a fronteira em duas direções:

  • Data center (Instinct): MI100 a MI250 no Linux agora têm backend ROCm oficial dentro do llama.cpp distribuído pelo Lemonade.
  • Consumidor (iGPU Strix): geração de imagem experimental nas iGPUs Strix Halo e Strix Point — o terreno do Ryzen AI Max e da memória unificada que os modelos de 30B quantizados tanto gostam.
Nota de honestidade: o release cita explicitamente Instinct MI100/MI200/MI210/MI250 (Linux) para LLM e Strix Halo/Strix Point para o backend experimental de imagem. Suporte AMD existe e é tema central do projeto, mas não validamos nesta publicação o comportamento em nenhuma GPU específica — para o seu hardware, a referência é a documentação oficial de instalação e a matriz de compatibilidade do repositório.

A leitura prática: o Ollama continua sendo o caminho de menor atrito para começar; o llama.cpp puro dá o controle fino (e é o que usamos no guia de execução local); o Lemonade se destaca quando o seu hardware é AMD e você quer GPU+NPU no mesmo serving, MCP sem cola manual ou rotação de backends sem trocar de cliente.

Como instalar

Binários oficiais da v11.6.0 por plataforma (links no release notes):

# Windows
lemonade.msi (instalador desktop)

# Ubuntu 24.04+
# Launchpad PPA: ppa:lemonade-team/stable

# Debian 13 / Fedora 43-44
lemonade-server_11.6.0-debian13_amd64.deb
lemonade-server-11.6.0-fc43.x86_64.rpm

# macOS
Lemonade-11.6.0-Darwin.pkg

Docker, Snap e demais opções estão na documentação oficial de instalação. Depois de instalado, o serving segue o padrão OpenAI (/v1/models, /v1/chat/completions) — qualquer cliente que fala com Ollama-compat ou OpenAI aponta para o Lemonade.

Caveats

  • Não comparamos throughput nesta publicação. Sem benchmark local no seu hardware, "mais rápido que X" seria chute — o lemonade bench existe justamente para você medir no seu setup.
  • Imagem via TheNoise é experimental e o suporte LLM ROCm citado cobre as Instinct no Linux; iGPUs Strix aparecem na nota para imagem, não como stack LLM validado.
  • Breaking changes da v11.6 afetam automação existente (audio/speech, listagem de quants, layout MSI) — leia o changelog antes de atualizar.
